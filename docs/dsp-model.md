# DSP behavior and remaining matching work

The engine has separate portable Scene and Isolate processors with bounded PMR audio storage and smoothed performance controls. Static factory Isolator, Echo and default Noise have now been fitted against the original RMX-1000 Plug-in 2.2.0 at 48 kHz. Noise uses statistical acceptance with original project excitation. Other effects, gestures, User profiles and hardware equivalence remain unverified. The [capture workflow and current results](audio-matching.md) state the measurement scope.

The [25 October sound-matching investigation](../research/audio/rmx1000-fidelity.md) reviews primary sources, the current DSP and measurement gaps, and proposes a capture and fitting campaign with explicit accuracy criteria.

The source references are Pioneer's [operating manual, effect types on pages 15–17](https://manualzz.com/doc/79710635/pioneer-rmx-1000-dj-effector-owner-s-manual) and [remixbox manual, parameter ranges on pages 12–14](https://manualzz.com/doc/58880568/pioneer-rmx-1000-remix-station-owner-s-manual). The linked pages are mirrors of the manufacturer-authored manuals.

## Sound research: 23 October 2026

This pass investigates the reported weak drum timbres and static-like Noise sound. Evidence is a source review and manufacturer documentation, supplemented by first-party DSP research. No listening comparison against hardware, new audio measurements, DSP changes or live-app restart was performed in this pass.

### What the reference specifies

Pioneer's operating instructions describe Noise as internally generated white noise passed through a band-pass filter and echo. Main moves the filter frequency, Sub1 changes noise level and Sub2 applies modulation. White noise itself is therefore expected; the audible identity depends on the filtering and control response. See the manufacturer-authored [Noise description](https://www.manualshelf.com/manual/pioneer/rmx-1000/user-guide-english/page-16.html), available through a manual mirror.

The manufacturer-authored [remixbox Scene table, page 12](https://pioneer.manymanuals.com/audio/rmx-1000-m/user-manual-4510/12) lists separate Noise width, minimum/maximum level, modulation/resonance modes and waveform choices. It does not establish the numerical frequency curve, Q, modulation rates, echo calibration or stereo behavior. Those require captures.

The [remixbox X-Pad table, page 14](https://pioneer.manymanuals.com/audio/rmx-1000-m/user-manual-4510/14) specifies per-drum gain, three decay choices and two envelopes. Pitch has separately configurable negative and positive ranges up to twelve semitones each. Our global +/-24-semitone control and fixed generated assets do not reproduce this complete sound-shaping model.

### Findings before the sound revision

| Area | Observed implementation | Likely consequence / work needed |
| --- | --- | --- |
| Kick | `makeFactoryBank` in `src/core/Engine.cpp`: a swept sine tending toward 45 Hz, short noise click and single exponential amplitude decay | A usable placeholder, with no measured reference transient, pitch contour or saturation. Fit these independently. |
| Snare | One 170 Hz sine plus unfiltered white noise, with separate but simple exponential decays | Limited body modes and a broad noise tail. Model the transient, body and filtered snare-wire component separately, or use cleared reference assets. |
| Clap | High-passed noise with a pulse term that repeats every 11 ms throughout the decay | Can sound buzzy or like a fluttering noise burst. Prototype a finite initial burst cluster followed by a separately filtered diffuse tail; derive timing from the reference. |
| Hi-hat | High-passed noise with a short exponential decay | No explicit metallic ringing component. Add measured resonant/inharmonic content or a suitable recorded asset. |
| Drum playback | One-shots use two-point linear interpolation; pitch changes sample speed | No dedicated anti-alias stage when reading faster than one source frame per output frame. Upward pitch and downsampling need a band-limited reader. Loops have a separate overlap-add path. |
| Noise | `src/core/Scene.cpp`: mono xorshift noise, a state-variable band-pass, optional tilt, amplitude modulation and feedback echo | Already filtered. The current 25 Hz to 18 kHz exponential sweep, Q choices and gain compensation are project values. The source review cannot identify the audible cause with certainty. |
| Noise modulation | Sub2 changes amplitude depth and a rate of `0.25 + 3.75 * Sub2` cycles per beat | The depth/rate coupling and intermediate rates are guesses. Match modulation destinations, rates, depth and side-chain behavior from captures. |
| Noise echo | Fixed one-beat delay, global feedback and a 0.5 return multiplier | Functional routing, with unmeasured timing, damping and balance. Avoid tuning the dry noise alone. |
| Output headroom | Protection is transparent below unity and approaches 1.25 above it | Summed music, drums and Noise can exceed digital full scale downstream. Check gain staging separately from timbre; clipping is a possible contributor, not an established diagnosis. |

The existing eight-millisecond performance smoothing and topology-preserving state-variable filter are useful foundations. Retain them while reviewing the 32-sample coefficient update cadence, switching transients and gain changes. Wishnick's [Time-Varying Filters for Musical Applications](https://www.dafx.de/paper-archive/2014/dafx14_aaron_wishnick_time_varying_filters_for_.pdf) supports this filter family for changing parameters; it does not supply RMX calibration.

For drum synthesis, Vult's first-party [VCV Drums development account](https://www.vult-dsp.com/post/making-of-the-vcv-drums) demonstrates separately modeled noise filters, transients and metallic ringing informed by measurements. This is a design approach for prototypes, not evidence that the RMX uses those circuits or drum-machine sources.

### Recommended implementation order

1. Capture a reference set before defining sonic acceptance thresholds. Start with the four drums at neutral gain/pitch and each decay/envelope combination: 24 settings, with repeated hits to check variation. Preserve onset, pitch contour and full tails. Measure the effect of gain and pitch separately.
2. Replace the snare/clap/hat placeholders first, then fit the kick. Pre-render synthesized assets during preparation so the callback remains bounded. Preserve current preset IDs and separate internal drums from user sample banks. Track the provenance of any assets distributed with the project.
3. Prototype Noise sweep, Q and level changes against stationary reference settings. First isolate the noise with silence at the input and modulation off; then compare slow/fast sweeps, resonance, each waveform and echo tails at several BPMs. Keep the white source for the reference mode; offer other colors only as explicit extensions.
4. Add the documented per-drum gain/decay/envelope model and asymmetric pitch ranges. Implement band-limited one-shot pitch/sample-rate conversion with explicit CPU and memory budgets for desktop and firmware.
5. Review final output headroom and perform level-matched comparisons on isolated hits, rapid rolls and music. For stochastic noise, compare averaged spectra, envelopes, echo timing and stereo correlation rather than requiring a sample null. Check 44.1/48/96 kHz, control sweeps and repeat triggering before promoting a sound revision.

No verified redistributable factory drum pack was established in this research. Pioneer's [official software page](https://www.pioneerdj.com/en/support/software/effector/rmx-1000/) documents the original plug-in as another possible comparison source; compatibility and access must be checked before relying on it. Exact factory timbre remains unverified until reference audio is available. Improvements to subjective sound can proceed in a separately reviewable prototype meanwhile.

## Sound revision: 23 October 2026

The first implementation of the research recommendations is a separately built sound revision. The running app is not replaced or restarted. This is original project voicing; there are no new hardware captures or claims of sonic parity.

- **Drums:** `FactoryDrums.h` pre-renders a saturated swept kick with a separate click, a multi-mode snare body with filtered wires, three finite clap bursts with a diffuse tail, and a hat with inharmonic ringing plus filtered noise. Preparation applies a DC blocker, end taper and per-instrument peak normalization. Internal drums and desktop starter banks use these assets; imported user samples remain their own sources.
- **Per-drum settings:** fourteen parameters are appended after the existing IDs: four gains, four decay choices, four envelopes and two pitch ranges. Internal drum gain is -3 to +3 dB; decay offers Short/Default/Long. Type 2 adds a short punch contour and faster tail. Choices are captured on each new hit and follow source playback time as pitch changes. Their numeric curves are project values. They are available in the existing native advanced-settings dialog and plugin parameter editor, with normal Default/User recall. Imported samples do not receive internal-drum envelope processing.
- **Pitch ranges:** the old `x_pitch` ID and -24 to +24 travel domain remain compatible. Separate down/up endpoint settings scale the two halves of travel; defaults retain the previous +/-24-semitone extension. Setting an endpoint to 12 gives a one-octave bend on that side. Values 1 through 12 cover the documented hardware options; 13 through 24 are extensions. The parameter name now identifies pitch travel rather than promising that its raw value always equals effective semitones.
- **One-shot playback:** integer unity reads are unchanged. Slower reads use cubic interpolation; faster reads use a 64-tap Blackman-windowed sinc with interpolated phase/cutoff tables and a guard band. Tables are compile-time read-only data, about 280 kB, without a callback initializer or additional sample-bank copies. There is no added playback latency. Finite filters are not alias-free at every extreme source/output-rate ratio; stopband rejection, maximum-voice CPU cost and embedded deadlines remain unmeasured. The loop stretch path is unchanged.
- **Noise:** white noise is retained. A dedicated 90 Hz to 12.5 kHz sweep, tighter width choices, partial energy compensation and a 12.5 kHz polishing filter shape the signal. Sub1 uses a smoother squared-amplitude curve when its minimum is Off. Modulation uses subdivisions of 1/4, 1/2, 1, 2 or 4 cycles per beat, with gain edges smoothed over 2 ms. Resonance mode bypasses that LFO. The one-beat echo is damped at 6.5 kHz and returned at 0.4; its send is no longer activated twice near Main's lower end. A frame counter suppresses previous-effect delay contents without clearing the delay allocation inside the callback. These are auditionable project tunings, not measured RMX factory maps.
- **Output protection:** linked stereo sample-peak gain replaces the old above-unity saturator. The ceiling is 0.9995, with immediate gain reduction and a 50 ms release. A LIMIT lamp below the output meter shows reduction greater than about 0.18 dB. No lookahead or latency is added. This is not a true-peak limiter and does not establish the downstream DAC's intersample headroom. Below the ceiling, with no prior limiting, gain is unity.

`rmx_sound_preview` is an optional build target for offline auditions. It opens no audio device and refuses an existing output directory. It writes 21 clips: four drums at -12/0/+12/+24 semitones, four fast rolls and a Noise sweep. Each clip receives one constant audition gain, targeting 0.05 RMS over its active duration with a 0.9 peak cap; `manifest.csv` records the actual levels. This is a listening deliverable, not a regression or hardware-conformance suite.

The arm64 native Mac app, AU and VST3 compiled for review. No automated test suite, real-device soak, firmware deadline run, alias-rejection measurement or original-unit listening comparison was performed for this sound revision. Earlier test counts and performance measurements apply to their earlier snapshots. The next review should compare the offline pairs and exercise gain/decay/envelope settings before promoting this revision for live use.

## Measured Noise update: 26 October 2026

`CalibratedNoise.h` implements a fitted third-order IIR with numerator `b0*(1-z^-2)` and a 21-point shape-preserving coefficient/gain map from public original output measurements. It uses independently excited project noise in the two channels. At 48 kHz with Normal width and modulation mode, this replaces the earlier mono source, provisional sweep, bandwidth and gain compensation. The static Sub2-zero result passes the [documented statistical screen](audio-matching.md#noise-identification-and-statistics); the original random generator is not reproduced.

Default Noise level now uses the measured −18/+6 dB span and central deadband. Its half-beat echo has a 0.35 first return and 0.5 feedback, without the earlier return damping. It continues after Noise is disabled. Other rates, widths and resonance settings retain the earlier project implementation. Modulation shapes, activation/release trajectories, User curves and effect switching still need measurement. Historical Noise values above describe their earlier revision.

## Isolate

`include/rmx/Isolator.h` / `src/core/Isolator.cpp` own the state for each selected audio bus. At 48 kHz, the factory Isolator matches fourth-order Linkwitz–Riley branches at fitted crossovers of approximately 284 and 4649.04 Hz: low is LP4, mid is HP4 followed by LP4, and high is HP4. The branches sum directly, without phase compensation on low/high. The active centre therefore changes phase. Trans/Roll and Gate/Drive have the same measured neutral response and use these branches; their non-neutral processing remains unmatched. Cut/Add retains the earlier first-order project split pending its separate fit.

`isolate_on` is appended after existing host parameter indices. It defaults off, and pressing a selected section button toggles it off. Knobs do not affect the disabled section. Older presets lacking the parameter retain enabled routing, as those versions always ran the section.

- **Isolator:** individual per-band minimum choices of −6, −12, −18 dB or full kill; maximum choices of 0, +3, +6 or +9 dB. Factory full kill / +6 dB uses measured 8-bit travel: raw 0–1 is kill, 124–131 is unity, and 254–255 reaches +6 dB. The two remaining spans interpolate amplitude linearly. Raw position maps from the bipolar knob through `floor((control+1)*127.5)`. Other User endpoints use the same interpolation as a project extension; their original curves have not been measured.
- **Cut:** a filtered bass/transient detector estimates the kick component. LOW reduces that detected component; MID high-passes the remaining signal; HI low-passes it. MID/HI filter resonance and kick-reduction strength are independently configurable. The detector currently uses a 180 Hz low-pass, 1 ms attack, 25 ms fast-envelope release, 250 ms baseline, 120 ms retrigger exclusion and 90 ms decay. These are tunable project values, not extracted hardware constants. Simultaneous instruments can overlap the detected component.
- **Add:** clockwise controls add delayed audio from their respective original bands. Each band has its own User pattern. The current Pattern 1 taps are 1/8, 1/4, 1/2 and 1 beat; Pattern 2 is 1/8, 3/8, 5/8 and 7/8; Pattern 3 is 1/4, 1/2, 3/4 and 1. Gains decay across taps. These tap patterns have not yet been matched to the three original pattern choices.
- **Trans:** counterclockwise position selects a musical rate and cut depth. The phase follows the performance beat, including Nudge. A short edge slew avoids discontinuous gate transitions. Three per-band rate maps are available; the original maps/waveforms remain unmeasured.
- **Roll:** clockwise engagement records a forward band window and repeats it. Window length follows the per-band beat map. It does not repeatedly recapture the preceding history. Changes to rate restart acquisition; matching the original's change-of-rate/capture-boundary behavior remains outstanding.
- **Gate:** uses a linked stereo band envelope with separate gain attack/release rather than gating at individual waveform zero crossings. Each band has Mild/Default/Wild depth.
- **Drive:** per-band saturation and depth, with level compensation. The original transfer function/oversampling and aliasing behavior remain unmeasured.

## Scene performance controls

The parameter IDs `scene_depth`, `scene_time`, and `scene_resonance` remain stable. Their displayed meanings are now Main, Sub1 and Sub2. Sub1 retains its old numerical 0–7 range for preset/host compatibility, but is continuous for Noise/reverb level changes. Tempo effects select one of four Sub1 regions. BPF Echo, Echo, Spiral Up/Down, HPF/LPF Echo and Crush Echo each store four independent User divisions. Choices run from 1/16 through 2 beats; Echo additionally permits 4 and 8 beats. Noise and reverb keep continuous Sub1 level controls. Noise uses a fixed one-beat internal echo, so its volume knob no longer changes echo time. That fixed time remains provisional.

| Effect | Main | Sub1 | Sub2 |
| --- | --- | --- | --- |
| BPF Echo | Band-pass cutoff | Echo division | Output modulation or filter resonance |
| Echo | Added echo-return level; dry stays at unity | Echo division | Output filter cutoff |
| Noise | Generated-noise filter cutoff | Generated-noise level | Modulation or resonance |
| Spiral Up | Spiral delay-window length | Feedback echo division | Upward pitch amount |
| Reverb Up | Reverb amount, additive dry path | Reverb level | High-pass output cutoff |
| HPF Echo | High-pass cutoff | Echo division | Output modulation or resonance |
| LPF Echo | Low-pass cutoff | Echo division | Output modulation or resonance |
| Crush Echo | Bit reduction | Echo division | Output modulation |
| Spiral Down | Spiral delay-window length | Feedback echo division | Downward pitch amount |
| Reverb Down | Transition from dry to reverb | Reverb level | Low-pass output cutoff |

These replace the former generic Sub2-to-feedback mapping. Echo repeat feedback is now independent of Sub2. Feedback character is stored separately for each applicable effect. Echo has filter width and Hold/DJM settings; the earlier filter-type option remains a project extension, rather than a claim that remixbox exposes that option. Hold/DJM controls the feedback mode; Hold freezes the circulating delay when Main reaches its full end.

Factory Echo now uses measured static transitions at raw 66, 132 and 194, with divisions of 1/4, 1/2, 3/4 and 1 beat. Its Main gain is `clamp((raw-3)/189,0,1)`. The default output filter is a second-order Butterworth high-pass, with fitted cutoff `60*exp(max(rawSub2-4,0)*0.0168583737)` Hz and Q = 1/√2. Feedback is 0.7; the shared feedback default has been updated accordingly. Echo and calibrated Noise first truncate `60000/BPM` to whole milliseconds before applying their beat division. Original integer/fractional-tempo captures support this timing rule. Auto follows external clock in the plug-in; Auto off holds manual BPM. Resting controls now use original Auto-on, Main/Sub2 zero, Sub1 raw 128 and the Echo Release selection.

Other Scene modes still use provisional equal-quarter regions and 1/8, 1/4, 1/2, 1-beat defaults. Their feedback/control maps remain unmatched. Echo's assignable User maximum is still exercised at 40 BPM, producing a 12-second delay. Gesture hysteresis, tempo changes and User settings require further captures. Selecting Echo for Release does not establish a measured Release model.

BPF/HPF/LPF/Noise have separately saved modulation-versus-resonance modes, waveforms and resonance character. Supported waveforms are triangle, saw, square, deterministic sample-and-hold random, and side-chain. The current modulation acts on output amplitude; the exact original modulation circuit, rate/depth maps and side-chain behavior must be measured before sonic matching can be claimed. Filter width and Noise min/max level choices are stored independently. The old global Noise Color is retained as a project-specific tilt option; 0.5 leaves the generated noise untilted.

Spiral uses a two-head, crossfaded delay pitch shifter inside the echo feedback path. Sub2 controls pitch independently of Main's window length, with Linear/Key variation and a configurable window span per direction. The current maximum shift is an octave. The original pitch range, head windows, feedback filtering and trajectories remain unmeasured.

Reverb uses an eight-line Householder feedback matrix with damping, two room sizes and three decay-time choices per direction. Feedback gains are derived from the chosen decay time rather than from Sub2. Each direction now has a separate low-pass/band-pass/high-pass User choice. The defaults are high-pass for Up and low-pass for Down; Sub2 moves the cutoff in the direction documented above. Original diffusion, early reflections, stereo field, pitch behavior, room sizes and decay maps still require a reference comparison.

## Sampler playback

`SamplePlayback` stores One-shot/Loop and original sample BPM independently of Default/User advanced effects. Loop mode is accepted only for slot 1 of each bank, with BPM 70–200, following the remixbox sampler editor. A pad press starts/stops a loop; strip/sequence starts reuse its voice without toggling it off. The engine wraps fractional reads safely and interpolates across the last/first frames. One-shot playback includes the last frame, including one-frame assets. Pitch and sample-rate conversion apply to both playback modes; loop speed also follows performance BPM divided by original BPM. An allocation-free stereo overlap-add reader now separates loop tempo from pitch; neutral playback retains direct interpolation. See [sample stretching](sample-stretching.md) for synthetic checks and transient/aliasing limits. Original loop time-stretch, timing, voice limits and choking still need reference measurement.

`SampleBank` contains four internal drum assets separately from its sixteen bank slots. Internal sources are always one-shots; SD replacement changes only bank slots. `sample_source` selects internal drums or bank samples independently of the live-input roll selector. Queued/host hits capture their source and bank; overdub stores that identity plus explicit loop-stop events. Changing the current selection therefore does not redirect existing voices or recorded hits. Firmware boots with the four synthesized internal drums and empty sample banks; desktop factory banks retain the project's sixteen synthesized variants. Original factory recordings are not supplied.

Presets persist `sample_mode` records alongside WAV references. Older presets default to One-shot/120 BPM and bank playback; new presets store source selection. Native and plugin import/preset paths validate the shared 16-second per-bank storage limit before installing assets. General WAV decoding remains available at 8–192 kHz. A separate strict PCM reader and `rmx_card_export` prepare/load 48 kHz sample banks using the project card layout; original RSD/SD interoperability remains unfinished. The native trim editor adds Loop/BPM, and the plugin adds a playback dialog. Native editing writes a managed WAV; metadata remains in the preset/session. Preview, card-availability feedback and the complete original sampler workflow remain unfinished.

`rmx_sampler_tests` covers separate internal/bank playback, queued and sample-offset source capture, mixed-source overdubs, loop start/stop replay, four-bank looping, one-shots/final frames, short buffers with large fractional steps, host BPM/pitch/rate conversion, Panic, metadata roundtrips/legacy source defaults, invalid slots/BPM and the exact 16-second bank boundary. Bounded-arena and global-allocation checks run active sampler loops alongside the existing effects and input roll. These checks do not establish hardware sonic matching or DAW certification.

The eight X-Pad positions now have separate User beat assignments. The sixteen choices follow the remixbox X-Pad table on page 14, including 1/24, 1/12, 1/6, 1/3, 2/3 and 3/2 beats. Default uses the previous project layout, retaining saved User choices. Sample repeats and new live-input captures resolve the same layout; desktop strip labels show those effective values. The preallocated capture is twelve seconds, covering eight beats at 40 BPM. Timing uses double-precision beat divisions and rounds capture duration to the nearest frame. `rmx_xpad_tests` measures all sixteen repeat intervals, quantized host-grid triplets, embedded touch assignments, Default/User restoration, legacy preset positions and full-length capture/replay. Held live-roll division/pitch changes, Slip/Divide modes and gesture overdub remain unfinished; the default layout and phase behavior still require reference-unit comparison.

## User settings and compatibility

`ParameterInfo::advanced` identifies custom settings. Default uses their factory defaults in DSP while retaining the saved User values; selecting User restores them. Native settings now scroll through the full set with named choices, and plugin parameters expose those choices to hosts. Old presets receive defaults for missing fields. SceneTime fractions roundtrip without being rounded to integers. DSP behavior intentionally changes where the former mapping contradicted the reference functions; older presets are not guaranteed to sound identical to the previous approximate algorithms.

The parameter model does not yet cover the entire remixbox schema. Independent crossover settings for each isolate mode, echo application-range settings, sample/oscillator settings, all release-lever ranges, effect locks/button sensitivity and RSD/SD conversion remain required.

## Verification

`rmx_isolator_tests` checks neutral stereo for every mode, all gain endpoints, additive eighth-note timing, kick reduction versus sustained bass, residual high/low-pass behavior, Trans rate changes, forward band capture, absence of waveform-cycle gate chopping and state roundtrips.

`rmx_scene_tests` checks neutral Main, Noise volume/filter/side-chain behavior, Echo onset and unchanged feedback across Sub2 extremes, channel isolation, HPF/LPF action, resonance None, room-size reflection timing, reverb control roles, Spiral pitch direction/amount, four-region assignments at every Echo division and the slowest supported BPM, Default/User restoration through the engine, Echo filter width, all three reverb filter choices, and fractional/per-effect state roundtrips. These are functional signal measurements, not reference-unit golden files.

`rmx_memory_budget` runs every Scene/Isolate combination and live roll against a real bounded allocation resource. `rmx_benchmark` now covers all 40 Scene/Isolate combinations with positive and negative knob settings. Both are host checks. Cortex-M7 timing, converter measurements, musical listening fixtures and original-unit matching remain unverified.

All delay lines share `FractionalDelay`. Integer index wrapping avoids a floating-point boundary that could round a read position to one past the buffer end. Regression coverage includes one-ULP positions around wrap/region boundaries, interpolation over multiple wraps, reset and nonfinite ages. AddressSanitizer/UndefinedBehaviorSanitizer checks cover the full core suites.

SD loading is a pre-audio operation. Each bank is replaced atomically, including empty slots, with one bank of temporary PMR storage. The same decoder is exercised by memory-file tests and exporter roundtrips; the FatFS adapter uses an AXI SRAM bounce buffer. `USER.TXT` now loads a separate snapshot of the implemented advanced settings with bounded, allocation-free parsing. It preserves performance/physical controls, commits after successful file close and leaves sample loading independent. The exporter can write User settings, samples or both; native Pioneer formats, live card insertion and nonvolatile User storage remain unfinished. Hardware cache/card/boot tests remain unverified. See the SD layout and preparation instructions in [hardware/README.md](../hardware/README.md).
