# NF05S — standalone sequential startup checkpoint (249 parts)

This new schematic derives from the captured 233-part NF04R READY circuit. It supplies the previously unmapped ARM/START functions locally: N19 waits for actual source SAFE and watchdog ENOUT, retains ARM until GLOBAL-OFF, then starts through an independently delayed Schmitt driver. N12 is enabled only after N19 COMPLETE **and** protected-output READY. No PC or unmapped MCU GPIO supplies these commands. The four old J1 command pins are output monitors and must not be driven externally.

The actual native export contains 249 components, exact physical-pin/value parity, zero ERC errors and the two unchanged isolated-secondary GND1 warnings. No PCB is implemented. Four relay symbols now include actual physical NC lead 3. Six DCU package selections use TI's actual 0.85×0.30 mm lands at 3.10 mm column spacing/0.50 mm pitch, copied from the reviewed FPC manufacturer pattern. Actual CWD capacitors are C1206C563J5GACTU / C1206C333J5GACTU (maximum body heights 1.35 / 1.00 mm); the old generic 0805/50 V choices were unsupported. Values are unchanged.

`generated/analysis.json` separates conditional timing, normal input power and provisioned heat. The TPS3890 START delay is approximately 33.77–76.11 ms under the stated complete capacitor/leakage/reset-response requirements. Its typical 200 Ω CT discharge is **not** used as a manufacturer maximum: ≤1 kΩ discharge, ≤0.5 ms assertion response, ≤50 nA CT leakage, ≥1 ms recognized GLOBAL-OFF and ≤25 ms clamp-release/gate-settle time are unaccepted receiving requirements. A qualified GLOBAL-OFF interval has not been proven for the actual E28 AUX reset/recovery path.

ARM is retained after SAFE falls, so a fault cannot erase its own qualification. Watchdog waiting starts before ARM; missing SAFE does not leave an indefinite unmonitored wait. The successful START creates one falling WDI edge; a fault clears PERMIT and makes the opposite edge, which does not pet this watchdog. START remains high while ARM is retained and cannot create a fresh retry edge. The pre-SAFE wait is separate from the loaded post-START conduction deadline. Maximum loaded cutoff/current, PhotoMOS release, pass-FET linear SOA and fault energy are not qualified.

The new feed is two 402 Ω resistors per module. The receiving output ceiling is 25.2 V for startup, no-load and transients; 22.8 V minimum applies only once settled, never throughout the 0→24 V ramp. At VIN=0 the initial output-power screen is 0.81428 W, or 0.97713 W with 20% planning margin; the old 26.4 V/392 Ω case required 1.09977 W with that margin. Actual TMR module startup/continuous hot behavior and the correlation “settled module voltage before first ARM” are unverified. Existing INTVCC/source SAFE does not independently measure the isolated 24 V module output.

A complete per-package AUX ledger replaces the old 150 µA aggregate logic assumption. Conditional provisions are 9 mA normal and 11 mA during nonrail-input fault states, **inside** the existing 90 mA source pool; acceptance of that pool partition, source regulation, returns and local LDO temperature remains false. The module change and the explicit DIG 2.42 A receiving proposal produce a provisional whole-inside capacity screen of 37.15034 W. Its normal 11.4 V/0.36 Ω feed point is separate (2.82607 A, 10.38261 V at the board). Neither is a measured heat/current upper bound. Raw fan stall, fault/standby and source-collapse states still require separate analysis.

Known safety defect retained in this checkpoint: AUX-powered logic is not specified throughout AUX 0.8–2.0 V while RAW5 remains live. A separate RAW5 absolute-AUX clamp-supply gate is being developed in `../absolute_aux_gate/`; it is not silently credited here. Intermediate-power corruption, AUX overvoltage, stale-state recovery, module-input return injection, harnesses, all source-to-load windows, stability/noise, thermal paths and fabrication remain unaccepted. All physical, startup and release flags remain false.

Run `python -m unittest hardware.qualification.boards.startup_negative_circuit.standalone_sequence.test_sequence`. The tests inspect the actual exported native cone, mutation-detect unsafe ARM/watchdog/sequencing changes, check source freshness and preserve unknown cutoff/qualification states. `handoff.json` freezes this checkpoint; parent sources/live routing are unchanged.
