# Source-bound I²C bus review

The current signal PCB does **not yet connect the whole bus**: native DRC records four open connections on LINK_SCL/LINK_SDA, including the A_R201/A_R202 pull-ups. The native schematic also includes A_U201 ES9292QPRO at address0x18, but its footprint is deliberately absent pending approved package information. `audit.json` records the exact open items and source hashes. The sensor PCB's clean local DRC never established these main-board connections.

Run `python -m hardware.cad.two_board_sensor_05.i2c_bus.audit` from the repository root. It reads the actual signal03 PCB/netlist/DRC, the power candidate, checked sensor PCB, manufacturer Trill C3 PCB, and current hardware firmware. It does not modify them. The power board has no LINK_SCL/LINK_SDA endpoints. Current signal copper totals are SCL202.814mm with5vias and SDA164.559mm with14vias; additional routing and the missing codec will increase loading. The eight-layer board declares thickness but no dielectric stackup, so copper lengths alone do not prove capacitance.

The schematic's single2kΩ±1% pair goes to shared3.3V. The custom sensor has no pull-ups. Manufacturer Trill Craft C3 has no bus pull-ups and has100Ω series resistors on SCL/SDA. Confirm the purchased module revision and reject added pull-ups or hub boards unless recalculated. Keep Trill at default0x30; address0x36 would collide with AS5600. MCP straps in the actual PCB decode to0x20/21/22. The Seed module's actual revision and disabled internal pull-up configuration remain receiving/configuration checks. Treat unused D_J1006/A_J402 stubs as part of the bus, and prohibit extra cables on them without updating the budget.

Retain400kHz. With Rmax2020Ω, the RC300ns ceiling is175.28pF per line. Proposed design allocation150pF gives256.73ns nominal exponential30–70% rise at Rmax:80pF signal board including Seed/three expanders,10pF missing codec/future local routing,15pF sensor,15pF Trill,30pF all external wires/mates. These are **acceptance allocations, not extracted or measured capacitances**. Vendor stackup/field extraction or a powered capacitance/rise-time measurement must demonstrate each allocation. If the10pF codec allowance is exceeded, rebudget before acceptance.

For a hypothetical200mm sensor cable, a cable accepted at100pF/m contributes20pF per line, leaving only10pF for Trill cable and all mates. This is a scenario, not an approved cut length. The harness owner confirms no final I²C route or cable specification exists. [3M3365 data](https://multimedia.3m.com/mws/media/22052O/3m-round-conductor-flat-cable-050in-3365-series-ts0080.pdf) provides47.5pF/m for its stated ground-signal-ground test geometry; that figure cannot simply be assigned to a four-wire adjacent-SCL/SDA harness. Final routing, ground arrangement, connector pinout and cable receiving capacitance must be explicit.

At a proposed3.3V±5% rail the worst pull-up current to zero is1.75mA; Trill's100Ω adds up to175mV to a remote sink path. This current calculation is not a universal VOL guarantee. MCP23017's published DC table specifies0.6V at3mA/1.8V and0.8V at3mA/4.5V, while its input-low limit is0.2VDD. It supplies no directly interpolatable3.3V guarantee in that table. Verify VOL at every receiver while each device ACKs, across chosen supply/temperature limits; proposed acceptance is≤0.5V, leaving127mV below0.2×3.135V. Confirm high level≥0.8VDD at each receiver and actual timing at its threshold. No low-level margin claim is made without this evidence or manufacturer confirmation.

The intended `hardware/firmware/full_engine` target includes the shared `BoardIO.h`; both current hardware firmware paths support the actual AS5600, Trill and MCP devices. The older `firmware/daisy` target is not authoritative here. Current successful reads consume180SCL clocks per front-button+AS5600 loop; external profile adds36 for rear status. Trill reads16bytes every4ms (171clocks); external codec polling adds up to216clocks every4ms. At the nominal1ms control gating this is55.69% onboard or78.19% external bus utilization at400kHz, excluding all software/start/stop/stretch/retry/LED overhead. An external coincident batch needs at least1.5075ms wire time, so the1ms gate is not a hard1kHz timing guarantee. At100kHz the same nominal demand is312.75%; lowering speed is not an adequate fix.

AS5600 functionality already reads status+raw angle and rejects missing/weak/strong field. Calibration accepts200..700counts;35° gives398.2counts, so the new lever travel is within the programmed range. No sensor-driver implementation is missing on inspection. Next concrete work is the four I²C routing repairs, codec package/placement completion, final harness and stackup budget, then actual bus/field/calibration and loop-latency tests. Firmware changes should follow a specific measured or reproducible failure, rather than replacing the current drivers.
